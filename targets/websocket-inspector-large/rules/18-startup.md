# App startup performance

- Cold start to first frame stays under 1 second at p50 on the reference mid-range device; a regression over 10 percent blocks release.
- `Application.onCreate` does only what the first frame needs: crash reporting, DI graph, strict mode in debug. Everything else is lazy or deferred.
- SDK initializers go through AndroidX App Startup with explicit dependencies. Remove auto-initializing content providers you do not need.
- Never do disk or network I/O on the main thread during startup. `StrictMode` catches it in debug builds; fix, do not suppress.
- Defer non-critical work (prefetch, cache warmup, analytics flush) until after the first frame with `reportFullyDrawn` or a post-draw callback.
- Ship a baseline profile generated by a Macrobenchmark journey for launch and the main scroll paths. Regenerate it when those paths change.
- Keep the launcher activity light: a splash via the SplashScreen API, no heavy layouts, no blocking reads of preferences.
- Measure with `adb shell am start -W` and Macrobenchmark, not with stopwatch timing in logs.
