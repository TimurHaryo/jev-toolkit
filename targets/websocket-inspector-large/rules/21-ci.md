# CI pipeline and required checks

- Every pull request runs, in order: build and unit tests, lint and static analysis, assemble release, instrumented tests on a sharded emulator matrix. All four are required checks.
- The pipeline for a typical change finishes under 20 minutes. A step that pushes it past that needs caching or sharding, not a longer timeout.
- Gradle build cache and configuration cache are enabled in CI. Cache keys include the wrapper version and the version catalog hash.
- CI runs the same Gradle tasks developers run locally; no CI-only scripts that nobody can reproduce.
- A flaky test is quarantined within one day: tag it, file an issue with the failure log, and assign an owner. Retrying a pipeline until green is not a fix.
- Never merge with a red required check, and never mark a check optional to get a change in.
- Artifacts (APKs, test reports, lint reports) are kept for 14 days so reviewers can inspect failures.
- Main branch builds publish an internal build automatically after every merge.
